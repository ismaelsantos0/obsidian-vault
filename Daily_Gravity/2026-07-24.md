# Daily Gravity - Histórico de Decisões

**DATA:** 2026-07-23 a 2026-07-24
**ASSUNTO/PROJETO:** Tradução de UI, Engenharia de Grafos e Projeto Tinta (ERP/Tintométrico)
**ASSUNTO DE FATO:** Ajuste de código frontal, documentação de conceito inovador (Graph Engineering) e Arquitetura de Software Modular.

**O QUE FOI DECIDIDO E FEITO:**

### 1. Tradução do Journey Mapper
- **Recusado pelo usuário:** A IA sugeriu aplicar lógicas ao sistema de agendamento, mas o usuário vetou fortemente: *"NÃOO, NADA DE APLICAR NO AGENDAMENTO"*, exigindo que o foco fosse documentação no Obsidian.
- **Aprovado e Feito:** Tradução completa da UI (`journey-map.html`) para PT-BR, convertendo todos os termos e implementando o visual de "Mapa de Fluxo".

### 2. Engenharia de Grafos
- **Estudo:** O usuário enviou tweets (Vivek Sen e OpenShip) mostrando uma forma inovadora de orquestração de IAs paralelas.
- **Aprovado e Feito:** A IA pesquisou e criou uma documentação robusta chamada `Engenharia_de_Grafos.md` no Obsidian para servir de base conceitual para os fluxos do usuário, abordando "Fan-ins" e tolerância a falhas. Foi salva na pasta de Recursos.

### 3. Projeto Tinta (ERP e Tintômetro)
- **Recusado pelo usuário (Visual):** A IA sugeriu Python nativo (PyQt) ou Electron. O usuário recusou o Python (por ser "muito feio") e o Electron/Web (por gastar muita memória, considerando o hardware alvo de um i3 8ª Gen com 8GB RAM).
- **Aprovado e Feito:**
  - Foi criado um modelo de **Monolito Modular** (`Sistema Base` + `Módulos de PDV, Estoque e Tintometria`).
  - A Arquitetura foi definida e documentada como **Tauri (Rust) + React** no frontend (visual web lindo consumindo ~20MB de RAM) e um **Python Sidecar** rodando dormente em background para fazer os cálculos físicos de mistura de tinta (Kubelka-Munk).
  - O sistema de Banco de Dados será `SQLite` local operando de forma 100% *Offline-First*, com um CRON job diário sincronizando backup para a nuvem.
  - Toda essa engenharia foi estruturada em uma pasta própria no Obsidian (`20_Dominio_Profissional/02_Projetos/Projeto_Tinta/`) e o arquivo antigo foi deletado.
  - O versionamento (`git push`) foi executado e atualizado no GitHub do usuário.

### 4. Criação da Regra Primordial (Daily Gravity)
- **Decisão:** O usuário exigiu a criação de um log diário documentando todas as respostas, projetos, acertos e recusas de todo o histórico.
- **Aprovado e Feito:** Uma Regra de Sistema (`daily_notes.md`) foi injetada no núcleo do Antigravity via comando `/learn`, forçando todas as IAs a gerarem registros padronizados nesta pasta (`Daily_Gravity`) a pedido do usuário.
